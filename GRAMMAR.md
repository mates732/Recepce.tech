# MINDSPACE — Grammar

Voice is how the website sounds.
Grammar is how the website thinks.

Every page follows the same cognitive cycle.
Visitors should recognize the structure
before they recognize the content.

---

## The Cycle

```
Question → Observation → Experiment → System → Question
```

This is not a linear path.
It is a loop.
Every ending produces a new beginning.

A **question** is noticed.
An **observation** is made about the question.
An **experiment** is designed to test the observation.
A **system** emerges from the experiment.
The system reveals a new question.

This cycle is the grammar of Mindspace.
Every page follows it.
Every section follows it.
Every sentence can follow it.

---

## Page Grammar

Every page answers one question
and follows the cycle.

### Structure

```
1. The Question — what prompted this page
2. The Observation — what was noticed
3. The Experiment — what was built or tried
4. The System — what emerged
5. The New Question — what this reveals next
```

Not every page needs all five.
But every page must know where it sits in the cycle.

### Page types by cycle position

| Page | Primary cycle stage | Role |
|---|---|---|
| Homepage | Question | "What is this?" |
| About | Observation | "How does this person think?" |
| Experiments | Experiment | "What is being explored?" |
| AI Receptionist | System | "A question that became useful" |
| Contact | Question (new) | "What happens next?" |

### Page rhythm

Every page starts with space.
Then the question appears.
Then silence.
Then the observation.
Then silence.
Then the experiment.
Then silence.
Then the system.
Then silence.
Then the new question.

The silences are not empty.
They are where the visitor thinks.

## Content Grammar

Every piece of content follows a sentence-level pattern.

### The pattern

```
[Subject] [was noticed / was built / became / revealed]
```

Not:
"The AI Receptionist is a cutting-edge solution."

Instead:
"A question became useful."

### Sentence positions in the cycle

| Cycle stage | Sentence role | Example |
|---|---|---|
| Question | Opens with curiosity | "Can a voice feel natural?" |
| Observation | States what was seen | "Most conversations fail because the technology is visible." |
| Experiment | Describes what was tried | "A system that listens before it speaks." |
| System | Names what emerged | "Voice memory. Conversation patterns. Quiet responses." |
| New Question | Points forward | "What happens when the system starts asking questions?" |

### Content density

One idea per paragraph.
One paragraph per section.
If a section has two ideas, it needs two sections.

### The silence rule

After every statement,
leave space for the visitor to think.

Not literal whitespace (though that too).
Structural silence: do not follow a statement
immediately with another statement.
Let the cycle breathe.

## Naming Grammar

Everything on the website has a name.
Names follow rules.

### Entity names

| Type | Naming rule | Example |
|---|---|---|
| Question | A question mark is required | "Can memory be structured?" |
| Observation | A statement of fact, not opinion | "Conversations have patterns." |
| Experiment | A noun, not a verb phrase | "Voice Memory" not "Building Voice Memory" |
| System | A compound noun or single word | "Conversation Engine" not "AI Conversation System" |
| Page | A single noun or noun phrase | "Experiments" not "My Projects" |

### Section names

Sections are named by what they contain,
not what they do.

| Instead of | Use |
|---|---|
| About Me | About |
| My Work | Experiments |
| What I Do | Process |
| Contact Me | Contact |
| Services | What I'm building |
| Testimonials | Observations |
| FAQ | Questions |

### File names

Files follow the entity name,
lowercase, hyphenated.

```
voice-memory.ts
conversation-engine.ts
ai-receptionist.ts
```

Not:
```
voiceMemorySystem.ts
ai_receptionist_final.ts
```

## Relationship Grammar

Entities are connected.
Connections have meaning.

### Relationship types

| Relationship | Meaning | Direction |
|---|---|---|
| questioned | X questioned Y | Y prompted X |
| observed | X observed Y | Y was noticed through X |
| experimented | X experimented with Y | Y was tested in X |
| emerged | X emerged from Y | Y produced X |
| evolved | X evolved into Y | X became Y |
| depends_on | X depends on Y | Y must exist for X |
| contradicts | X contradicts Y | X and Y cannot both be fully true |
| supports | X supports Y | Y is strengthened by X |

### The grammar of connection

Every entity should know:
1. What questioned it into existence
2. What it observed
3. What experiment it produced
4. What system emerged
5. What question it now asks

This is the entity's cycle.
It mirrors the page cycle.
It mirrors the site cycle.
The same grammar at every scale.

### Scaling the grammar

```
Site cycle:    Question → Observation → Experiment → System
Page cycle:    Question → Observation → Experiment → System
Section cycle: Question → Observation → Experiment → System
Sentence:      Subject → Was noticed → Was built → Became
```

The grammar is fractal.
It works at every level of zoom.

## Story Grammar

The website tells one story.
Not many stories. One.

### The story

"A question about connection became a system
that connects.
The system raised new questions.
The questions became new experiments.
The experiments became new systems.
The cycle continues."

This story is told across pages,
across time,
across iterations.

### Story structure

```
Act 1: The Question (Homepage)
  — What is this?
  — A mind at work.

Act 2: The Process (About)
  — How does this person think?
  — Observation, not opinion.

Act 3: The Experiments (Experiments)
  — What has curiosity produced?
  — Things that emerged from questions.

Act 4: The System (AI Receptionist, specific projects)
  — What became useful?
  — Questions that found answers.

Act 5: The New Question (Contact / future)
  — What happens next?
  — The cycle continues.
```

### Story rhythm

The story is not told all at once.
It unfolds.
Each visit reveals a new layer.
Each iteration adds a new chapter.

The visitor should feel
they are arriving in the middle of something
that has been happening
and will continue
after they leave.

---

## Evolution Grammar

The website changes.
Change follows rules.

### What evolves

| Element | Evolution rate | Rule |
|---|---|---|
| Grammar | Never | The cycle is permanent |
| Voice | Rarely | Only when the thinking changes |
| Vocabulary | Slowly | New words earn their place over time |
| Content | Each iteration | New experiments, new observations |
| Visual | Each iteration | Changes follow the grammar |

### The iteration rule

Every iteration answers one question:
"What is the next experiment?"

Not:
"What features should we add?"

The website evolves like a organism.
Not like a product roadmap.

### What stays permanent

The cycle.
The vocabulary.
The tone.
The silence.

Everything else can change.

---

## Application rules

1. Before writing any content, identify its cycle position.
2. Before naming anything, check the naming grammar.
3. Before connecting two entities, identify the relationship type.
4. Before publishing, verify the content grammar.
5. When in doubt, remove. Silence is always correct.
